Apa itu Enkapsulasi? (Encapsulation)

Enkapsulasi adalah mekanisme membungkus data (variable) dan metode (method) yang bekerja pada data tersebut menjadi satu kesatuan unit (class), serta menyembunyikan rincian implementasi dari akses luar.

Keamanan Data
Validasi Terkontrol
Fleksibilitas Refactoring

Analogi Kasus: Brankas vs Dompet Terbuka

Bayangkan saldo bank seperti uang tunai di tabungan Anda:

  • Tanpa Enkapsulasi (Public): Seperti meletakkan dompet terbuka di meja kantin. Siapapun bisa mengambil uang, mengubah jumlahnya, atau memasukkan uang mainan tanpa izin.
  • Dengan Enkapsulasi (Private + Getter/Setter): Seperti mesin ATM. Anda tidak bisa menyentuh lembaran uang langsung di dalam mesin. Harus lewat antarmuka kartu & PIN (Validation), lalu tarik/setor sesuai aturan.
Kesimpulan Guru: Data penting harus dikunci (private) dan hanya bisa diakses via pintu resmi (Getter/Setter).

Bahaya Mengapa 'saldo' Tidak Boleh Public

Jika atribut saldo bersifat public, hal-hal berbahaya ini bisa terjadi secara tidak sengaja maupun disengaja:

// DANGEROUS CODE EXAMPLES:
akun.saldo = -5000000; ❌ Saldo bernilai negatif!
akun.saldo = 999999999; ❌ Cheat / Manipulasi Data
akun.saldo = akun.saldo - 10000; ❌ Tanpa cetak struk/log!
Solusi Enkapsulasi: Perubahan saldo wajib melalui aturan logika bisnis seperti setor(double jumlah) atau tarik(double jumlah) dengan syarat validasi.

Studi Kasus 1: Perbankan (Kasus Saldo Rekening)

Bandingkan struktur kode Java sebelum menggunakan enkapsulasi dan sesudah menerapkan aturan Enkapsulasi standar industri.

SEBELUM Enkapsulasi (BURUK) Public Variable 
public class RekeningBank {
    // BAHAYA: Variable public dapat diakses siapa saja!
    public String nomorRekening;
    public String namaPemilik;
    public double saldo; // <-- RISIKO TINGGI!

    public RekeningBank(String no, String nama, double saldoAwal) {
        this.nomorRekening = no;
        this.namaPemilik = nama;
        this.saldo = saldoAwal;
    }
}

public class MainBank {
    public static void main(String[] args) {
        RekeningBank akun = new RekeningBank("123-456", "Budi", 500000);
        
        // BISA DIPERMAINKAN TANPA VALIDASI:
        akun.saldo = -99999999; // Tidak masuk akal tapi VALID di sintaks!
        
        System.out.println("Saldo saat ini: " + akun.saldo);
    }
}
❌ Dampak Kerugian:
1. Saldo bisa bernilai negatif tanpa halangan program.
2. Tidak ada pencatatan riwayat (audit log) saat nilai saldo berubah.
SESUDAH Enkapsulasi (AMAN) Private + Getter/Setter 
public class RekeningBank {
    // TERTUTUP: Atribut dilindungi dengan 'private'
    private String nomorRekening;
    private String namaPemilik;
    private double saldo;

    public RekeningBank(String no, String nama, double saldoAwal) {
        this.nomorRekening = no;
        this.namaPemilik = nama;
        if(saldoAwal >= 0) { this.saldo = saldoAwal; }
    }

    // GETTER: Pintu Khusus Membaca Data
    public double getSaldo() {
        return this.saldo;
    }

    // METHOD BISNIS TERKONTROL (Deposit)
    public void setorTuna(double jumlah) {
        if (jumlah > 0) {
            this.saldo += jumlah;
            System.out.println("Berhasil setor: Rp" + jumlah);
        } else {
            System.out.println("Jumlah setor harus positif!");
        }
    }
}
✅ Keuntungan:
1. Saldo terlindungi dari perubahan ilegal (akun.saldo = -100 akan Error Compile!).
2. Menjamin data integritas melalui instruksi terstruktur.

Studi Kasus Kontekstual SMK: E-Kedisiplinan & Poin Karakter

Di sekolah SMK, setiap siswa memiliki Poin Kedisiplinan (Awal: 100 Poin). Jika siswa terlambat atau melanggar aturan, poin akan berkurang. Jika mengikuti lomba/prestasi, poin bertambah.
Problem: Jika variabel poinKarakter bersifat public, siswa nakal dapat mengubah poinnya sendiri menjadi 1000 dengan mudah!

Implementasi Class SiswaSMK.java

Encapsulated Rules 
public class SiswaSMK {
    // Attributes bersifat PRIVATE agar aman dari peretasan/perubahan liar
    private String nisn;
    private String nama;
    private String kelas;
    private int poinKarakter; // Default: 100

    // Constructor
    public SiswaSMK(String nisn, String nama, String kelas) {
        this.nisn = nisn;
        this.nama = nama;
        this.kelas = kelas;
        this.poinKarakter = 100; // Poin awal sempurna
    }

    // Getter Poin (Hanya Membaca)
    public int getPoinKarakter() {
        return this.poinKarakter;
    }

    public String getNama() {
        return this.nama;
    }

    // Method khusus mencatat Pelanggaran (Mengurangi Poin secara terkontrol)
    public void catatPelanggaran(int poinPengurangan, String jenisPelanggaran) {
        if (poinPengurangan > 0) {
            this.poinKarakter -= poinPengurangan;
            if (this.poinKarakter < 0) this.poinKarakter = 0;
            System.out.println("[SISTEM] Pelanggaran '" + jenisPelanggaran + "' dicatat. Poin berkurang " + poinPengurangan);
        }
    }

    // Method khusus mencatat Prestasi (Menambah Poin, Max 100)
    public void catatPrestasi(int poinBonus, String deskripsi) {
        if (poinBonus > 0) {
            this.poinKarakter += poinBonus;
            if (this.poinKarakter > 100) this.poinKarakter = 100; // Maksimal poin 100
            System.out.println("[SISTEM] Prestasi '" + deskripsi + "' dicatat. Bonus Poin: " + poinBonus);
        }
    }
}
